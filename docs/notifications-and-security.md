# 多群提醒与服务器防护（2.4.0）

## 管理群与选择收件人

班干进入「QQ 提醒设置」，可维护最多 10 个 QQ 群的名称和群号，指定默认群。机器人须已加入目标群并具备发消息权限。访问令牌独立填写，留空保留同一机器人原令牌；页面不会回显令牌。「保存并测试机器人」仅检查登录状态，不向群或同学发送测试消息。

公告、文件任务、问卷、分组、活动和班会的 QQ 群通知，发送前均弹出群选择窗口，可同时选多个群。原来的默认群配置自动兼容。

2.4.1 起，群选择窗口可勾选「@全体成员」，每次打开默认关闭，仅对本次选中的群生效。发送前逐群检查机器人权限及剩余次数；检查失败、无权限或次数不足的群不会发送，结果会列出原因，可取消勾选后发送普通通知。私信及邮件不显示此开关。群消息使用正式的 OneBot @ 消息段，正文中的文字不会被当作 @ 指令执行。

QQ 私信、邮件提醒同样先选择收件人，可按姓名、学号、号码搜索，选择当前搜索结果或清空。未填写有效联系方式的用户不能勾选。公告新增 QQ 私信按钮；教材订购明细、宿舍明细和失败邮件重发也支持选择收件人。个人教材明细只包含本人订购，宿舍长只收到对应宿舍内容。班会记录既可发给系统用户，也可清空用户勾选后使用原输入邮箱。

文件未提交、问卷未填写、未分组、未签到、未订购等提醒，只显示相应待办名单。真正发送前再次核验；若勾选后已有同学完成，返回状态变更提示，重新打开选择窗口即可。取消窗口不会发送消息。发送结果区分全部成功、部分失败和服务繁忙；不要反复点击发送。

公告多图与附件仍沿用现有模板。群内直接发送的图片单张最多 256 KiB、文件最多 1 MiB；QQ 私信图片最多 64 KiB，其他大附件使用有效期 7 天的受签名保护链接。邮件继续使用小附件与大附件链接策略，保留下载并发和带宽控制，减少多群、多收件人的重复大文件传输。

## 服务器状态

班干管理视图新增「服务器状态」。展示应用容器 CPU、容器内存、宿主可用内存、磁盘剩余、当前网络收发、最近一分钟请求/拦截数量、正在处理请求，以及临时封禁、安全事件和告警结果。首次采样的速率显示待采样，页面可见时每 15 秒刷新。数据来自只读系统信息，无需 Docker 控制权限。

默认防护针对 API 请求，适合单进程部署与约 50 人共同使用：

| 项目 | 默认值 |
| --- | --- |
| 同一来源 10 秒请求 | 300 |
| 同一来源每分钟请求 | 1800 |
| 全站 10 秒请求 | 1500 |
| 同一来源每分钟登录/重置请求 | 120 |
| 同一来源每分钟登录失败 | 30 |
| 连续超限来源临时封禁 | 300 秒 |
| 告警合并冷却 | 300 秒 |

单次来源突发先返回 HTTP 429 和 Retry-After；10 秒内连续 3 次超限后临时封禁该来源。全站突发短暂限流 5 秒。原有单账号登录、文件并发和提醒接口限流继续有效。校园网可能共享出口，阈值预留了 50 名同学各发起 5 个请求的余量。班干可解除临时封禁；仅系统管理员可修改防护阈值或告警开关。

异常首次发现后立即加入后台投递，邮件与 QQ 私信两个通道并行处理，收件人为所有管理员及标记为班干的用户。不会发送给普通同学或自动发送到全部配置群。每个通道按有效联系方式去重；缺少联系方式、未配置服务、投递失败会显示在服务器状态中。请先补齐班干邮箱与 QQ，并配置 SMTP 和机器人。

同一冷却期内不重复轰炸提醒；通道繁忙最多尝试 3 次，间隔 15 秒；已尝试提交给服务商的消息不盲目重试。实际送达取决于 SMTP、机器人和网络，后台处理不会阻塞普通请求。

## 数据和部署

本次不增加或修改数据库表及字段。多群配置、防护设置和有限的安全历史存放在现有 DATA_DIR 的 JSON 文件，随数据卷持久保存；重启后请求计数和临时封禁重新累计。来源最多记录 4096 个、安全事件 100 条、告警结果 30 条，后台只保留一个合并告警，限制内存与任务数量。生产保持单 worker；多副本部署时需改用共享限流存储。

应用防护能减少异常 API 消耗；3 Mbps 链路若被流量打满，需通过云平台或上游网关防护。反向代理只应信任实际代理地址，并覆盖客户端传来的转发头。候选容器和测试使用 `SECURITY_ALERT_DELIVERY=0`，防止测试触发真实提醒。此次仅更新网页与后端，安卓安装包不更新。
